# Vio Studio v2.0 — Checkpoint 46
Date: 2026-11-21

## User-reported regressions
1. Solo OBS URL displayed the PNG avatar but did not apply the saved visual-effect configuration, did not animate Idle/Talking, and did not detect microphone input.
2. GO Collaboration no longer displayed Host/Join choices.
3. Collaboration avatar layout controls did not visibly change the local avatar.
4. Collaboration stage should use landscape dimensions so multiple participant avatars can be arranged side by side.

## Root causes confirmed by source inspection
- `AvatarRenderer.normalizeEffects()` interpreted an effect object without its own `enabled` property as disabled, even when the legacy profile had the global `effects.enabled=true` and stored that effect's parameters. The inspected Development profile uses this legacy shape; some nested effects have no per-effect enabled flag.
- Login restoration can set `currentRoom` to a `personal_overlay` room. `openRoomChooser()` treated any non-null `currentRoom` as an existing Collaboration room and returned before displaying Host/Join.
- Collaboration slider input updated `roomOverrides` but `renderRoomParticipants()` rendered the own participant from `member.overrides`. This left the live preview using stale values until another server/broadcast refresh.
- Collaboration shared-stage canvas inherited the host's personal profile resolution (often portrait). This was not appropriate for a row of participants.
- The clean OBS renderer previously depended on a Creator tab continuing to publish microphone state. The standalone overlay page itself did not instantiate `AudioEngine`, so a clean Solo overlay could be idle when the Creator tab was backgrounded or suspended.

## Changes made

### Solo OBS
- Imported `AudioEngine` into `src/overlay.js`.
- For `personal_overlay` rooms only, the standalone overlay now starts a local, invisible microphone capture using the host profile's device preference, sensitivity, and boost settings. If that device ID is unavailable on the OBS/browser host, the existing AudioEngine device fallback requests the default microphone.
- Local microphone state updates the host avatar's Idle/Talking state and therefore selects the matching expression and keeps the shared AvatarRenderer animation loop active.
- Collaboration overlay rooms continue to use each participant's Creator-side state broadcasts; the new local capture is not started for those rooms.
- Added a safety fallback for OBS CEF: if local capture starts but Creator publishes a `talking` state, the remote `talking` state is accepted. Local OBS capture suppresses only remote `idle`, not remote `talking`. This covers embedded Chromium runtimes where microphone access can be blocked or can fail to deliver actual samples despite a successful stream setup.
- No microphone controls, menus, or buttons were added to `overlay.html`. The visual output remains canvas-only. Microphone permission must be granted by the browser/OBS runtime. Debug-only mic diagnostics are available through `?debug=1`.

### Visual effects
- Updated `normalizeEffects()` so a legacy effect object without its own `enabled` field inherits the global effect toggle only when it contains saved effect settings.
- Explicit per-effect `enabled: false` remains false.
- Updated the editor's `buildEffectDefaults()` to display the same legacy behavior as the renderer. This keeps the Editor preview and OBS renderer consistent.

### GO Collaboration
- `openRoomChooser()` now distinguishes a personal Solo OBS transport room from a real Collaboration room. A restored Solo room no longer skips Host/Join.
- The chooser explains that selecting Host or Join closes the current Solo OBS room on this device. This is necessary because the backend currently allows only one active room membership per user/device.
- Room layout slider input updates the local participant's override object immediately before rendering. Persisted changes still go through `set_room_override` and Realtime broadcast.
- The reset layout action also updates the local participant model immediately.
- Collaboration shared-stage backing canvas is fixed at 1920×1080 (16:9), independent of participant profile resolution.
- OBS overlay rendering also uses 1920×1080 for Collaboration-purpose rooms; Solo personal overlays retain the host's saved profile output dimensions.

### Backend
- `overlay_connect` now returns `room.purpose`, allowing the clean overlay to choose the correct Solo or Collaboration behavior and output resolution.
- No SQL schema migration was required.

## CEF microphone compatibility follow-up
- OBS Browser Source uses CEF; its microphone permission path can differ from Chrome and may be unavailable. The clean overlay remains canvas-only and does not attempt to render permission controls.
- The Solo overlay now accepts Creator-side `talking` broadcasts even while local Solo capture is active. A local `idle` value is still used when Creator broadcasts idle, preventing ordinary stale idle updates from overriding the local detector.
