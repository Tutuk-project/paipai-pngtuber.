## Hard fixes — OBS overlay and GO Collaboration (20 November 2026)

### OBS overlay link
- Changed overlay URL construction to resolve from the v2 application module location, so GitHub Pages sub-path deployment does not accidentally resolve the overlay at the domain root.
- Added an OBS link dialog that exposes the complete URL and provides explicit Copy Link and Preview actions. The generated URL remains visible if the browser blocks clipboard access.
- Overlay runtime errors are now shown directly instead of being hidden on a transparent canvas. Invalid/missing credentials, Supabase configuration, anonymous session failures, Realtime failures, empty room membership, and missing avatar assets produce actionable diagnostics.
- The overlay still uses a transparent canvas for Browser Source; diagnostic text appears only when needed (or in debug mode).

### GO Collaboration mobile UI
- Replaced the static participant placeholder with a dedicated live notice area; removed the duplicate “Waiting for participants…” markup.
- Participant count is now based on the fetched room-members list. The view shows a loading state first and reports member/API errors or missing avatar PNGs explicitly.
- Rebuilt Personal controls into two grouped sections: Avatar layout (scale, horizontal position, vertical position, reset) and Audio input (microphone source, sensitivity, booster).
- Room controls now reflect server-persisted overrides after the member list loads, and device choices are refreshed after control re-render.
- Added mobile-safe toolbar button grid, bounded portrait canvas, contained participant labels, and responsive control cards to prevent horizontal overflow.
