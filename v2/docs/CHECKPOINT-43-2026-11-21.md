## Incident evidence
User screenshots showed:
1. GO Collaboration room 0533 could not load participants and displayed `[object Object]`.
2. Generated OBS overlay page showed `Edge Function returned a non-2xx status code`.

Supabase logs at 2026-11-20 22:43 UTC (2026-11-21 05:43 WIB) confirmed:
- `room_members` Edge Function request returned HTTP 400.
- Underlying PostgREST request to `vio_room_members` returned `PGRST200`.
- The failed select attempted to embed `vio_profiles` and `vio_characters` directly from `vio_room_members`.
- The declared foreign keys connect `vio_room_members.user_id -> vio_app_users.id`, and `vio_profiles.user_id / vio_characters.user_id -> vio_app_users.id`. There is no direct `vio_room_members -> vio_profiles` or `vio_room_members -> vio_characters` relationship.
- The same invalid relationship shape existed in both `room_members` and `overlay_connect`, explaining both reported failures.

## Changes applied
1. Both queries now embed profile and character data through `vio_app_users`:
   - `profile:vio_profiles!inner(preferences,active_character_id)`
   - `characters:vio_characters(...)`
2. Mapping code now reads profile and character data from the nested `vio_app_users` relation.
3. Membership lookup errors are explicitly thrown rather than silently treated as missing membership.
4. Edge Function catch handler now serializes PostgREST `message`, `code`, `details`, and `hint`, logs structured diagnostics, and returns HTTP 500 for database errors instead of incorrectly mapping unknown failures to HTTP 400.
5. OBS overlay catch handler reads JSON error details from Supabase FunctionsHttpError responses rather than showing only the generic SDK message.
6. Added a regression test requiring both room and OBS queries to use the valid foreign-key path.
