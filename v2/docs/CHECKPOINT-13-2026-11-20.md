## Completed in this checkpoint
1. Added migration 005: `vio_storage_cleanup_queue`, a service-role-only durable queue for failed private Storage object deletion.
2. Accessory deletion now records a cleanup job before deleting the metadata row. If metadata deletion fails, the job is explicitly cancelled so an Admin retry cannot remove a still-referenced object.
3. After metadata deletion, Storage removal is attempted. Failed removals remain pending in the queue with attempt count and last error.
4. Admin support deletion of accessories uses the same queue and records whether cleanup remains pending in the audit log.
5. Added Admin API action `admin_retry_storage_cleanup`, capped at 25 pending jobs per run.
6. Admin overview reports pending cleanup count and exposes a retry button.
7. User-facing accessory deletion reports when the database record is gone but Storage cleanup remains pending.
8. Added regression tests for queue ordering, cancellation, Admin retry and UI wiring.
