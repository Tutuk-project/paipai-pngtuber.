# Vio Studio v2.0 — Checkpoint 44
Date: 2026-11-21

## Incident
User reported PNG expression upload failure in Character & Assets:
- UI error: `Upload gagal: Unknown action: character_library`.
- Screenshot captured on Android Chrome at approximately 05:51 WIB.

## Root cause confirmed by source audit
A comparison of all `api("...")` calls in `v2/src/app.js` against the action handlers in `v2/supabase/functions/vio-api/index.ts` found five frontend actions with no backend handler:
- `character_library`
- `create_character_draft`
- `save_character`
- `set_active_character`
- `delete_character`

The existing `record_asset` handler also ignored the frontend `character_id` and selected a character named `Default`, which could associate an uploaded PNG with the wrong character.
The existing `record_accessory` handler had the same stale `Default` path/lookup assumption, despite the frontend uploading to a character-ID-based path.
The existing `my_assets` response omitted `character_id` and returned expression assets across all characters, which could mix assets when users have multiple characters.

## Changes
1. Implemented the five missing character-library actions with owner-scoped queries.
2. Added character draft creation, save, activate, and delete lifecycle.
3. `character_library` returns saved/draft state, selected-character state, and signed Idle preview URLs.
4. `record_asset` validates ownership and exact character-scoped Storage path, verifies uploaded object existence/size, records the correct character, audits the upload, and queues cleanup of a replaced object.
5. `record_accessory` now validates the selected character ID and corresponding Storage path instead of using `Default`; accessory uploads are audited.
6. `my_assets` now resolves the active character, returns its ID, and signs only that character's expression/accessory assets.
7. Failed expression uploads now clean up their newly uploaded Storage object. Audit-write failures after committed mutations are returned as explicit warnings so the client does not delete an object whose metadata has already committed.
8. Added regression tests for action coverage, character ownership, exact Storage paths, active-character isolation, and accessory path validation.
